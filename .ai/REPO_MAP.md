# Repository map compatibility seed

**STATUS: POINTER_ONLY**

The canonical tracked map is now **`.ai/APP_MAP.md`**. Read that file first.

This file remains only because `ai.ps1` and older agent workflows may still expect `.ai/REPO_MAP.md` to exist. Do not use this short compatibility seed to reconstruct the architecture from scratch.

## Canonical sources

1. `.ai/APP_MAP.md` — compact, current, versioned architecture/feature/data-flow map for any AI, including remote agents.
2. `AGENTS.md` — permanent operating/efficiency rules.
3. `.ai/runtime/REPO_MAP.md` — optional detailed local reconnaissance generated by `ai.ps1`; ignored by git.
4. Source code — final authority when implementation details differ from documentation.

## Minimal fallback

- Browser/PWA, vanilla JS/CSS.
- `index.html`: DOM shell and base script load order.
- `app.js`: very large legacy core; search symbols/IDs instead of reading wholesale.
- `piano-rooms.js`: current general addon loader despite its historical name.
- `data-core.js`, `sync-core.js`, resilience modules: data/synchronization.
- `event-*`, `planning-*`: events, competitions, projects and planning extensions.
- `professor-*`: virtual Professor, event-gated ranking, duration policy and ChatGPT handoff.
- `solidity-*`, `readiness-*`, `work-*`: musical state, recovery, structure and difficulty.
- `sw.js`, `update-safety.js`: PWA deployment/update safety.
- `tests/`: unit/E2E/visual verification.

## Local map generation

`ai.ps1` may generate `.ai/runtime/REPO_MAP.md` for deeper local navigation. Keep that generated map compact. It complements `.ai/APP_MAP.md`; it does not replace the tracked canonical map.
